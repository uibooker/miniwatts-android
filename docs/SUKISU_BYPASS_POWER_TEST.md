# 供电效果验证方法与当前采样

日期：2026-10-13，Asia/Shanghai。设备：Xiaomi 15 / dada，模块 0.2.0。

## 当前开启状态的只读采样

用户手动开启厂商 FCC 限流策略后，每约五秒读取一次电池电流、累计电量、温度、输入遥测与请求值，得到 13 个样本。此次未切换策略、未改变负载、未断开输入。

| 指标 | 结果 |
| --- | --- |
| 设备运行时间区间 | 742–804 秒，共 62 秒 |
| 聚合请求值 | 全部为 1104，bit 10 开启 |
| battery/charge_counter | 3,951,000 → 3,968,000 µAh |
| 累计电量变化 | 增加 17 mAh |
| 累计电量折算平均充电电流 | 约 987 mA |
| battery/current_now | -1,090,000 至 -860,000 µA |
| 瞬时采样平均电流 | 约 -1,021 mA |
| 电池百分比 | 全部为 77% |
| 电池温度 | 35.5–35.6°C |

单位按 Linux power_supply 属性约定换算。累计电量增加与负向电流的幅度一致，说明这段观测中负号对应充电方向。仅看百分比未变化会遗漏真实充电；该电量计有约 1 mAh 的量化阶梯，不能把单个阶梯不变当作零电流。

平均电流换算：

```text
平均电流(mA) = 累计电量变化(µAh) × 3.6 / 时长(s)
             = 17000 × 3.6 / 62 ≈ 987 mA
```

这段数据支持“电池仍在约 1 A 充电”，不符合运行时电池近零充放电的旁路效果。它没有验证策略关闭前后的限流差异，也不证明硬件在所有其他条件下均不支持旁路。

原始 CSV 位于 `.tooling/bypass-check/policy-on-passive-sample.csv`。

## 如何做完整对照

1. 选择约 40–70% 电量，避免满电降流、80% 充电上限等条件把普通充电伪装成零电流。固定充电器、线、屏幕亮度、应用、网络活动和温度条件。使用功率足够的输入；当前连接电脑时 USB 报告能力约为 5 V / 1.5 A，高负载下可能不足，应避免把输入不足导致的电池放电解释成旁路硬件故障。
2. 保持同一轻负载，做关闭 5 分钟、开启 5 分钟、再次关闭 5 分钟的对照。每次切换后先等待约一分钟稳定，再以约五秒间隔采样。记录请求状态、输入在线状态、电池 current_now、voltage_now、charge_counter、温度和百分比。最后恢复用户希望保留的状态。
3. 在输入功率充分时，对开启状态做轻负载和较高负载的重复观测。负载增加后若电池仍持续放电，则该条件下没有由外部输入独立维持运行。若累计电量近乎不变，但电池电流反复出现较大充电与放电，则只能说明净变化小，不能说明电池没有参与供电。
4. 如需校准电流符号，可另做短暂拔线的已知放电参照。但本模块在拔线后会保护恢复并结束会话；重新接线不会自动再次开启，必须明确重新请求。当前采样通过累计电量趋势已有充电方向证据，未实际执行拔线。

## 如何解释结果

- 关闭时充电明显，开启后仍持续充电但较慢：支持限流效果，不是电池近零充放电。
- 开启后持续充电或放电：该测试条件下没有达到电池近零充放电。
- 只有电量百分比不变、某个瞬间电流接近零、系统显示 Not charging 或请求位开启：证据不足。
- 输入在线且功率充足，在多个负载与多轮对照中电池电流持续接近测量噪声、累计电量无有意义趋势，并且系统负载增加由输入承担：支持运行时的旁路供电效果。阈值应依据传感器精度、量化和采样能力设定，不能用任意固定毫安阈值当成硬件认证。

软件遥测最多建立运行行为证据。若要声称电池物理隔离或某个 BATFET / 电源通路已切换，还需要充电芯片资料、确切寄存器含义、驱动调用链或板级测量。电池可能作为瞬间缓冲，低频采样会漏掉短时充放电。

已有驱动分析追踪到的是正 FCC 投票，没有发现明确电池隔离操作，见 `docs/XIAOMI_DADA_BYPASS_RESEARCH.md`。本轮采样与“限流而非零电池充电”的解释相符。
