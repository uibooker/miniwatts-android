# Xiaomi 15 / dada：旁路插件实施结论与最终交付

日期：2026-10-13。对象：24129PN74C / dada，OS3.0.303.0.WOCCNXM；沿用此前已审查的运行身份记录。本次把剩余的注册覆盖、公开源码、独立请求与恢复、ADSP/PMIC 末端和测量准入放在同一实施决策中收尾。

**当前不能交付已经实现真实旁路的新版插件。现有 0.2.0 仍是厂商 FCC 限流请求模块。** Linux 侧存在与输入控制分开的电池充电使能请求，但现有材料没有同时形成可安全调用的独立控制后端、可靠恢复及合格的电气验收。本次没有把未验证的候选打包成新开关，也没有用手机试写来补足这些证据。

这不是“已经证明硬件永远不支持”的结论。这里结束的是当前资料条件下的实施评估：可完成的离线调查与审查已经交付；实机旁路、适配代码和安装包仍有明确的技术阻塞，不能列为完成。

## 最后对比：为什么各候选不能接入

| 候选 | 能证明的功能 | 尚未满足的关键条件 | 本次决定 |
| --- | --- | --- | --- |
| 已有 smart_chg bit10 | 厂商温度相关的正 FCC 限流请求与回显 | 不提供电池持续净电流为零及输入承担系统负载的证明 | 保留为已有 FCC 能力，不改变版本或能力声明 |
| charge_enable 用户入口 | buck 投票可沿 provider 发送电池充电使能；quick 有另一条 CP 停止流程 | 用户空间缺自身 enabled=0 释放，setter 吞错误，quick 影响附带状态 | 不新增自动写入或手机试值 |
| smart_night / mishow / OEM SOC | 原生共享策略能条件申请与释放部分充电约束 | 无插件独立 owner；共享参数/快照/附带状态恢复不全；mishow 查询还可能写持久分区 | 不占用 OEM owner，不借全局策略模拟恢复 |
| LKM / KPM / opaque 内核适配 | 可以作为开发路线评估；内核已有投票、查询和重执行原语 | 对应版本的类型、绑定/存活、上下文、有效状态、下游完成与恢复仍未闭合 | 不生成依赖猜测的可加载后端 |
| 直接 GLINK / 寄存器控制 | 已定位有限的 Linux 请求和部分远端资料 | 不具备独立仲裁、完整远端/硬件定义、附带操作及失败恢复 | 不绕过策略层，不发送控制请求 |
| ACC 或其他手机方案 | 部分公开实现提供暂停/恢复或输入与充电分离的设计参照 | 无当前 dada 的完整适配契约；自动探测会试写 | 不安装试探，不当作本机已可用后端 |

恢复目标采用[既定方案](DADA_IMPLEMENTATION_NEXT_STEPS.md)的**功能恢复**：插件固定 owner 不再参与聚合，OEM 重新掌握控制，受影响状态得到确认。无须每次删除 owner 名字，也无须恢复到名字完全不存在；因此没有 remove-client export 本身不是本次不实施的充分理由。

同样，`mca_rerun_election` 有实际用途，但不能被描述为通用修复。它可重新调用当前有效回调并返回该回调结果；不能重算所有附带状态，也不能找回下游已经吞掉的错误。buck enable 回调保留 provider 的返回码，quick enable 回调在停止流程后强制返回 0；quick 的有效值回到非零时还会直接成功返回，没有同步重启硬件的配对动作。两条路径不能共享“返回 0 即硬件已恢复”的判定。

官方 `0x2003` 写入路径的消息格式已经有证据：class 将参数按 `&1` 取低位，proxy 传入 1 byte，GLINK writer 先将 256-byte payload 补零，再复制有效长度并发送固定 `0x114` 大小的请求。主调用读 byte、附带分支读 32-bit，在这条已审计路径中接收的是补零后的 0/1；消息长度与填充不再作为该路径的独立未知项。这个结论不能推广到其他 caller 或裸 RPC，也没有证明当前硬件的供电效果与完整恢复。

本次未用“find 返回裸指针、存在 destroy export”直接推导目标策略必有销毁竞态。可行性报告核对了实际调用范围；代码 pin、设备引用、绑定锁和 devm context 是不同的存活问题，必须证明保护的是相应的实际对象。仅能解析符号，或磁盘/加载模块声明 Build ID 相同，都不足以授权新增内核调用。

公开源码检索补查了四个固定 Xiaomi modules 仓库的完整归档普通文件；三个目标 MCA 核心符号的精确内容匹配均为零，外部 symlink 未跟随。失败的代码搜索接口按失败保留，不计为无源码。这个结果只覆盖所查提交，不扩写为所有分支或全网不存在实现。

KPM 另沿固定 SukiSU 源码和其官方文档指向的 KernelPatch 项目核对。该固定组合的默认符号导入路径不能据此承诺解析已加载的 MCA 模块 export，也不会自动持有这些模块的引用。显式获取模块符号与引用仍可作为开发设计；所查公开组合没有证明当前手机的对应能力，更没有解决驱动绑定和上下文生命周期。因此这里不把传统 Module.symvers 缺件作为所有 KPM 路线的否定理由，也不把能加载 KPM 当作 MCA 控制已经可用。

ABI 独审进一步核对了该固定 KPM 的名义 RCU 区间：helper 指针缺失时 wrapper 可以静默跳过，固定卸载代码也没有 grace period。它不能证明当前手机的实际 RCU 上下文或卸载行为；合法睡眠 worker、退出与卸载同步仍需对应实现的契约。

## 测量结果改变了验收门槛

`battery/current_now` 的上层分派可以吞下层返回码；下层还存在固定值、软件缓存以及成功返回但不写输出的条件分支。`charge_counter` 在此分派中取得策略剩余容量缓存，不能默认按节点名认作实时硬件库仑累计。新报告记录了原始分派、相关 flag 条件及必要 FG/provider 实现，没有声称这些分支正在手机上发生。

这使得“读取成功且电流为 0”不够作为验收依据。必须同时知道有效性、错误、真实测点、单位、方向、采样年龄与模拟/缓存状态。USB online 只说明软件在线状态。`get_vsys_volt/0x200c` 的远端 getter 实际请求 ADC 通道 0，名称表为 `VPH_PWR`；名称表中的 `VSYS` 是另一通道 2。主审采用[已确认的远端链](DADA_NEXT_TELEMETRY_RESEARCH.md)，修正早期仅凭 Linux `BUCK_VSYSMIN` 名称推断其返回设定值的说法。这条 ADC 链仍缺实际 provider、测点、单位和时效，尚未成为合格的 SYS 电压测量。

[受控验证方案](DADA_CONTROLLED_VALIDATION_FINAL.md)完整区分了进入条件、正常充电基线、候选控制、负载对比、退出与恢复和失败终止。目前控制、恢复及测量准入未通过，因而没有一套可以安全执行的控制命令或已完成的实机 A/B 数据。文件中的验收流程不能作为手机试写授权。

## 阻塞项及能改变决定的材料

要进入实现，需取得下列材料或等效的、可独立审查的实现证据：

1. **匹配控制与生命周期契约。** 当前构建的实际 MCA driver/include 及对应关系，或可证明同样边界的受限 opaque 接口：固定插件 owner，受控初始化后查询保证不新分配，enabled=0 释放，绑定/上下文存活，正确并发与 errno，部分执行和硬件失败可辨识。可以一次性预留固定 inactive owner，但必须证明其属于当前 voter 代际。LKM 构建资料或 KPM 加载支持只在选择相应路线时要求，不能互相替代控制契约。
2. **末端供电与恢复契约。** 与实际设备匹配的 ADSP charging handler、PMIC 修订/字段及板级通路，足以确认 0x2003 与输入供电的关系、buck/CP 模式转换、附带状态和退出后的确认方式。仅请求名、寄存器地址或其他机型资料不能填补这项。
3. **合格的测量链。** 实际 gauge/provider 的有效性、校准、单位/符号、采样时效和模拟/缓存状态，以及可信的输入测量；据此完成独立于软件请求的能量流和恢复对比。

这三项是技术阻塞；重复授予 root 或允许安装包不能使其通过。在取得对应材料前，不再将继续泛搜、读取更多属性或未经恢复审查的试写描述为完成插件的步骤。

- [ABI 独审](DADA_FINAL_ABI_INDEPENDENT_REVIEW.md)：检查投票/查询/重执行、源码检索范围、LKM/KPM 与 opaque 路线的阻塞理由。
- [供电及验证独审](DADA_FINAL_POWER_INDEPENDENT_REVIEW.md)：检查远端/PMIC 推论、测量原始分派及方案准入。
- [主线程关键原字节核验](../.tooling/bypass-check/final/root/key-evidence-review.json)：12 个完整 common 函数、1072 个 instruction words、6 张 ops 表和 48 个回调字段；没有执行作者生成器。
- [汇总交叉审查](../.tooling/bypass-check/final/root/aggregate-peer-review.json)：锁定作者与独审版本，记录审查发现、修订和最终静态结论。
- [最终保存核验](../.tooling/bypass-check/final/root/verification.json)、[完整交付清单](../.tooling/bypass-check/final/root/final-delivery-manifest.json)：报告、证据、来源、失败记录和独审材料的文件身份。

供电独审提出一项 P2：初版把官方路径已知的 payload 值、长度和填充列为待闭合协议。作者根据三个完整函数的原字节修正了第 3 节，保留[修订前快照、证据和限定变更记录](../.tooling/bypass-check/final/power/payload-contract-revision/revision.json)。本次采用修订后的官方 0/1 消息契约，去除这一额外未知项；硬件通路、附带操作恢复与有效测量的独立阻塞仍存在。注册和 ABI 独审没有新增实质问题，最终独审状态与身份由汇总文件固定。

供电作者的初版 Linux 验证器遇到 ET_REL 节范围问题：仅按地址选择 LLVM 输出时，其他节的同偏移被混入 `.text` 比较。最终窗口明确限定 `.text` 并逐字核对；原 KO 与函数原始窗口没有改变。[修订记录](../.tooling/bypass-check/final/power/linux-section-revision.json)保存首版清单及 18 个原命令的同字节输出重建，重建 SHA 与已记录 SHA 全部相等。原 stdout 没有事先留存，原失败 trace/stderr 也未保存在工作区，报告明确这项限制，没有将重建冒充原始采集。独审以最终修订身份为准。

本次基线冻结 1708 个先前文件及 35 个已有产品文件，不覆盖旧研究、既有安装包或工作区原有修改。当前任务的手机/ADB 命令、root 命令、充电属性读取、控制写入、HAL 调用、寄存器/内存访问、安装/加载和实机试验均为 **0**。此前只读运行身份记录仍按原时间和非原子快照边界使用，不冒充本次新采集。

交付验证只证明材料完整与静态结论有依据；真实旁路的实施与电气验收状态仍为 **未完成，因上述技术条件阻塞**。
