# dada 第四轮：运行身份、夜间恢复与无线回调的汇总审查

日期：2026-10-13。目标：Xiaomi 15 / dada / 24129PN74C，OS3.0.303.0.WOCCNXM。主代理负责读取已审查的手机身份信息、汇总和最后核验；三个子代理负责夜间契约、无线注册链、读取白名单与身份独审，随后交叉审查。

**18 个相关模块的实机声明构建身份、20 个静态文件摘要和 22 个已知链接目标已完成核对；夜间入口有禁用分支，但共享策略、电量快照和附加工作无法靠一个开关精确恢复。新增的无线回调还会改变输入限流、电压及充电泵。现有证据仍不足以把这些入口接入插件作为可恢复的物理旁路后端。** 插件继续保持既有 FCC 限流实现，本轮不生成新的控制包。

## 1. 现场身份与读取边界

当前手机的产品、ROM 和内核声明与既有分析目标一致。18 个选中模块的标准 GNU Build ID 与各自分析 ELF 相同，`initstate` 均为 `live`。18 个 `srcversion` 在正确返回码下确认缺失，缺失没有当作空字符串匹配。具体身份与原始字节见 [运行身份审查](DADA_RUNTIME_IDENTITY_STAGE4.md)。

MiCharge service、NDK 库和 18 份 KO 的存储文件 SHA-256 全部匹配官方分析工件。22 个固定链接均取得有效目标，明确了 class → platform → driver/module 的 `charge_interface`、`charger_partition`、`smart_charge` 绑定，以及既有 HL7603、SC8581、QCOM proxy、ADSP driver 绑定。特别是 `smart_charge` 最终指向 `soc:smart_charge` 和 `mca_smart_charge` 模块，权限失败没有被误当作路径缺失。

读取只包含固定的系统属性、模块标准元数据、已知链接与普通厂商文件摘要。没有读取 `smart_night`、`mishow`、充电电流等充电属性值，没有调用 Binder/HAL、设备 ioctl、debugfs、寄存器或内存接口，没有安装、加载驱动或修改充电策略。已有研究确认部分 getter 会产生写入，因此这里按具体实现选择白名单，不能把“读取”普遍当作无控制副作用。[R1][R2]

本轮采集处理了三个工具/权限边界，并保留各次原始证据：

- 首次采集停在电脑端 ADB 端口权限，固定手机请求为 0。
- 第二次使用 `exec-out`，部分权限报错混入 stdout，远端失败未可靠传回退出码。109 次传输不能当作 109 个有效读值；18 份所谓 note 实际是错误文本，不参与身份匹配。
- 第三次改用无 PTY 的 `adb shell -n -T`，取得有效的 18 组 note/initstate，并区分 srcversion 缺失。已知 class 链接的 canonical 解析返回非零且输出为空时按规则停止；空目标不解释为节点不存在。

随后只续采原白名单的 93 项子集：9 个系统身份请求、22 个路径的链接元数据/目标、20 个静态文件的元数据/摘要；不重复模块元数据。每个子集请求与原计划的对应 command 完全相同。同一路径先证实类型，再对明确权限不足或限定的矛盾 guard/空 canonical 失败进行一次 root 读取，root 身份先用 `id` 核验。每版脚本、计划和原始证据都保留 SHA-256，执行前由 metadata 子代理独立审查。原始采集不是原子快照，构建身份、静态文件和链接证据各自保留采集时间与边界。[R1]

| 采集记录 | 固定元数据尝试，含重试和 root-id 预检 | root 尝试 | 可采信结果 |
| --- | --- | --- | --- |
| 首次电脑端失败 | 0 | 0 | 无固定手机读值 |
| `exec-out` 失败 | 109 | 0 | 错误文本排除；不采用其模块身份 |
| module `shell -T` 窗口 | 103 | 37 | 18 note/initstate、18 srcversion 缺失；链接依赖失败停止 |
| 93 项子集续采 | 124 | 60 | 20 静态文件摘要、22 链接、系统身份；全部计划完成 |
| 本轮合计 | 336 | 97 | 两个有效证据窗口，不是 336 个成功读值 |

另外保留四次采集各自的 ADB discovery，以及开始时一次连接检查；这些连接枚举不计入上表固定元数据请求。主代理自有 ELF/note 解析器与 metadata 代理的独立结果一致。所有采集的充电属性读取、充电控制写入、HAL、debugfs 和安装/加载操作均为 0。

Build ID 相同支持“采集时已加载模块声明相同构建身份”；它不证明运行内存未被修补。文件摘要相同支持“该路径的存储文件与官方工件一致”；它不证明当前 service 进程正在执行该文件。链接只说明当时对象绑定，不证明 smart-charge registry 指针、ADSP 对端身份或实际供电行为。

## 2. 夜间接口：禁用入口存在，完整恢复仍不成立

[夜间契约](DADA_NIGHT_CONTRACT_STAGE4.md)补齐了原生 `smart_night` 的参数解析、查询、handler 和字符设备候选别名。

| 契约 | 实际行为 | 插件含义 |
| --- | --- | --- |
| 查询 | 仅返回保存的 signed 32-bit raw 整数 | 不包含阈值、电量快照、共享有效票或硬件状态 |
| 写入 | signed int/base0 解析；enable 保存低 16 bit；始终覆盖夜间上限为 80 | 一个全局 OEM 策略字段，没有插件 owner |
| 启用 | 非零 raw 重新采样启用时 RSOC；重算共享策略并异步排队 | 无立即停充或硬件完成确认 |
| 禁用 | 0 禁用夜间字段，随后重算 ENDURANCE_PRO/NAVIGATION/NIGHT/条件 mishow | 其他策略仍可能保持共享 SOC 限制 |
| 回写旧值 | 非零会重新采样 RSOC；零仍保留快照并覆盖上限 80 | 不能精确恢复操作前状态 |

夜间相关字段还有条件性的普通 CSD worker 消费者；handler 只取消 SOC work，不取消这条普通工作，也没有恢复旧 pulse mode 的配对动作。这里证明的是有条件的 type5/event54 分发，没有把它当作实际电池电流或完整 CSD 硬件语义。

单独的 sysfs 夜间 show 与 lookup 在配套包、正常初始化及对象存活条件下只访问软件内存。本轮仍未在手机读取该节点。字符设备 open/ioctl/mmap/close 处理另一个全局 4096-byte BAA 缓冲区，close 可派发参数更新，不提供夜间独立申请/查询/释放协议，不能作恢复别名或纯查询替代。

因此，“只有停充入口、完全没有关闭入口”需要修正为：**有 OEM 夜间禁用/重算入口，但没有得到插件独立所有权、完整状态查询和精确恢复承诺。** 有明确的 0 分支仍不满足旁路后端验收。

## 3. 无线回调：新增两槽与条件性回升

[无线注册链](DADA_SOC_REGISTRY_STAGE4.md)从官方镜像精确提取三份模块，补出普通无线 slot1 和快速无线 slot3。加上既有 buck slot0、quick slot2，静态建立 4/6 槽；slot4/5 未确定，不能推断为空，也不能把静态注册调用当作当前内存注册表。

普通无线使用固定 OEM `soc_limit` owner，按阶梯同时改变电池充电电流和无线输入电流，末端还请求禁充与 6V。逐步释放票没有保存旧电压或同步恢复所有硬件的协议；force-vout callback 的零值只清软件字段，没有立即请求原电压。快速无线进入 CP、ADC、模式、无线电压/电流和其他 OEM owner 的停止流程，零值中性票没有立即重启 CP 的配对回调。两条链都没有完整错误传播和失败回滚。

交叉审查发现并修订了一个 P2：普通无线 gate 为 0 时，只把当次 process 参数改成 false，缓存的原请求仍可能为 1。在原 step 为 2..10、排队成功、worker 运行且没有其他事件改写缓存/取消工作时，后续 worker 不复查 gate，可能降阶后再次升阶，包括 10→9→10 并重新申请票。最终报告和 [条件化原字节 trace](../.tooling/bypass-check/stage4/registry/basic-gated-request-trace.json)明确这些前提，没有声称该路径在当前手机发生。[R3]

这些新回调进一步限定了 OEM SOC 停充的作用范围：输入通路也受策略影响，不能靠充电电流票、接口返回值或属性名推出“电池停充且系统持续由外部供电”。

## 4. 独立审查与实现决策

| 工作 | 作者证据 | 独立审查 |
| --- | --- | --- |
| 夜间契约 | 8 个完整函数及 1 个 alternatives 辅助窗口；773 个 instruction words；52 个 data 窗口 | [夜间独审](DADA_STAGE4_INDEPENDENT_REVIEW.md)：1240 项检查通过，无需修订最终作者报告 |
| 无线注册链 | 18 个代码窗口：12 个完整函数、6 个局部窗口；1054 words；17 个 data 窗口 | [无线独审](DADA_STAGE4_REGISTRY_INDEPENDENT_REVIEW.md)：520 原始证据与 224 语义检查通过；P2 修订已复核 |
| 手机身份 | 主代理仅执行审查后的固定元数据请求 | metadata 代理独立解析 ELF/note、哈希、命令和权限分支；主代理另用独立解析器对照 |

两份代码独审都使用自己的 section/符号/RELA 解析及 fresh host LLVM，没有执行作者的提取/验证脚本。所有子代理的手机/ADB 操作为 0，手机采集由主代理统一执行。检查数量只描述证据覆盖，不作为插件功能验收。

本轮维持候选 OEM 后端不可用，不把 FCC 限流升级标注为物理旁路。要改变这个决策，仍需匹配版本的可用控制 ABI、独立请求的生命周期及释放、原状态完整查询、硬件完成/错误恢复，并分别证明外部输入持续供电和电池净电流/恢复行为。当前 root 权限和更完整的注册覆盖没有替代这些条件。

下一项有效推进应围绕具体的匹配 MCA/ADSP 控制实现及恢复契约展开；在取得可恢复入口前，继续增加 OEM 全局开关写入或用手机猜试值不能满足验收。本轮没有准备手机试写命令。
