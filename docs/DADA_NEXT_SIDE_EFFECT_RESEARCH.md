# DADA 0x2003 附带操作的下一轮离线取证

日期：2026-10-13。范围：本机已采集的 ADSP 固件 `adsp.b19` 至 `adsp.b22`、已解析的 Linux 模块 BTF，以及 Hexagon v79 反汇编。本文作者没有执行 ADB、手机寄存器访问、安装、插件修改或硬件试验。

## 1. 本轮结论

`0x2003` 的主操作已定位为 `PmSchgChgr_SetEnableCharging`。本轮继续追踪它的额外调用，得到以下结果：

- `ctx+0xbc` 的 ops `+0xd4` 是 FSW 设置业务路径；它与 `0x2004 / ADSP_PROP_ID_BUCK_SET_FSW` 走同一 wrapper。`0x2003` 启用分支调用参数 `(3, 5000)`，在已定位实现内转换为对地址 `0x2742` 写编码 0；对象模型 `0x4c/0x59` 使用 mask `0x03`，其余模型走参数 3 的分支、使用 mask `0x07`。没有证据把参数 5000 换算为 Hz、kHz 或 MHz。
- `+0xfc`、`+0x100`、`ctx+0xc0` 的 `+0x60/+0x90` 可以明确到字段写入地址、掩码和模型条件。现有证据未给出这些字段的准确名称或电气效果。
- 同固件内虽有 `PmSchgMisc_SetSmbEnCfg`、`PmSchgMisc_SetChEn` 等字符串，但本轮没有把这些名字可靠绑定到上述目标。不能用相邻表项顺序或 SMB5 中相同偏移替代该证据。
- 这些操作的返回值在 `0x2003` 外层没有汇总；主操作成功也不等于附带操作全成功。启用与禁用分支还不对称，不能据此实现“关闭后恢复所有原值”。

这是对固件静态程序的结论。当前运行时对象模型、传输选择器、SlaveID 和板级电源拓扑仍未知，**不能据此宣称已经取得安全可写的旁路接口**。

## 2. 基础与取证方法

此前的主链、初始化分支、payload 宽度和 getter 取证见 `docs/DADA_RECONNECT_PROVIDER_RESEARCH.md`。本轮沿用其中经校验的 `charger-analysis.elf` 和完整 `charger-v79.disasm.txt`，解析方式为 `--triple=hexagon --mcpu=hexagonv79`。地址属于本次采集固件，不能作为其他版本的固定地址。

段地址为：b19 `0x60000000`，b20 `0x601ca000`，b21 `0x602bf000`，b22 `0x602c0000`。b20 的大部分 memsz 为 BSS；运行时 ops 指针所在 BSS 的静态零不能当作运行时对象值。

本轮产物位于 `.tooling/bypass-check/reconnect-provider/next-side-effects/`：

| 产物 | 用途 |
| --- | --- |
| `direct-side-effect-windows.txt` | 五个实现函数的精确范围，以及共享 wrapper 和 2004 调用分支 |
| `local-branch-tables.json` | b19 中的实际 jump table 内容 |
| `named-hal-binding-audit.json` | 具名字符串、直接引用和 raw pointer 引用的范围与结果 |
| `supplemental-hal-windows.txt` | 同寄存器地址的其他 HAL 实现；保留未绑定名称的状态 |
| `exact-register-immediate-hits.json` | 目标地址在完整反汇编中的精确立即数命中 |
| `field-name-search.json` | 本地字符串调查候选；字符串存在本身不证明调用关系 |
| `manifest.json` | 来源、报告、产物的 SHA-256 与本轮访问边界 |

Hexagon 是 packet 架构，表中列出的地址是反汇编行地址。直接分支或 call 的目标以解码出的绝对目标为准，不把普通 ASCII 在可执行段里的位置误当成函数。

## 3. +0xd4：FSW 已从未知附带操作收敛到具体字段写入

### 3.1 业务名称绑定

共享 wrapper `0x6002e7e0` 从对象 ops `+0xd4` 取函数；已定位 factory 的该槽为 `0x6013acb0`。

另一调用来自 `mca_set_charger_buck_properties` 的 `0x2004` case `0x600315c0`。`0x60031664..0x60031678` 装载 `ctx+0xbc`，读取 payload32，并以参数 `(3, payload32)` 调用同一 `0x6002e7e0`。这条分支还在 `0x60031648` 使用字符串地址 `0x6016d916`，其内容为 `Info: %s: set fsw %d`。Linux 原模块 BTF 将 8196/`0x2004` 定义为 `ADSP_PROP_ID_BUCK_SET_FSW`。

因此，将该业务操作称为 FSW 设置有两条独立名称锚点。它不是根据启用分支参数 5000 猜出的计时器或投票操作。

### 3.2 启用分支参数的实际转换

实现 `0x6013acb0..0x6013afa8` 的第三参数以 32 位保存。对象首字节为模型字段：

| 对象模型条件 | 第三参数范围，按无符号比较 | 写入数据 | 地址/掩码 |
| --- | --- | --- | --- |
| `0x4c` 或 `0x59` | `<=6499` | 0 | `0x2742 / 0x03` |
| 同上 | `6500..8499` | 1 | 同上 |
| 同上 | `8500..10499` | 2 | 同上 |
| 同上 | `10500..13199` | 3 | 同上 |
| 同上 | `>13199` | 0 | 同上 |
| 其他模型，第二参数为 3 | `<=11999` | 0 | `0x2742 / 0x07` |
| 同上 | `12000..14999` | 2 | 同上 |
| 同上 | `>14999` | 7 或 4，由平台信息字段决定 | 同上 |

`0x2003` 启用分支传入 `(3, 0x1388)`，即 5000。因此两种模型路径都得到数据 0，但使用的掩码不同。其余第二参数分支存在，例如 mask `0x70`，不属于这次启用参数路径，不能混用。

最后调用 `0x6002d7e0(object, address, mask, data)`。该函数有传输选择器分派；已定位的选择器 0 经过 `0x6002da10` 到 `0x6005b330` 做 SPMI masked RMW。未观测运行时选择器，不把静态可达的 SPMI 分支当作本次运行时事实。

### 3.3 可证明的边界

同固件还有 `0x60083180` 对 `0x2742` 使用 mask `0x07`、`0x60083d20` 使用 mask `0xff`；它们在 DCDC 类 HAL ops 表的 `+0x28`。固件也存在字符串 `PmSchgDcdc_SetFswSel` (`0x60182706`)。但是本轮限定搜索没有找到从该名字到槽 `+0x28` 的可靠绑定，故不把这条补充链算作具名证明。

已证明的是业务 FSW 设置和具体编码写入。仍缺 **对应模型版本的 `0x2742` 字段定义、编码到物理频率的表、参数单位以及运行时对象身份**。编码 0 不是“0 Hz”；输入 5000 也不是已确认的 5 MHz。FSW 操作本身不能证明供电通路切换。

## 4. +0xfc/+0x100：0x2c42/0x2c43 的操作与条件

`+0xfc` 绑定 `0x6013bc60..0x6013bd04`。对象首字节以 unsigned byte 读取，再与 `0x46` 比较：

- 模型 `<=0x46`：返回 0，不执行目标字段写入。
- 模型 `>0x46`：先对 `0x2c42` 以 mask `0x02` 写第一参数的布尔值（0 或 2），再对同地址以 mask `0x01` 写第二参数的布尔值（0 或 1）。两个底层返回码在函数内按位 OR。

`0x2003` 非零分支参数 `(0,1)`，对应 bit1 清零、bit0 置位；零分支参数 `(1,0)`，对应 bit1 置位、bit0 清零。上面的模型条件适用时才会发生这些写入。

`+0x100` 绑定 `0x6013bd10..0x6013bd7c`：只有对象模型恰为 `0x47` 才对 `0x2c43 / mask 0x01` 写参数布尔值；其他模型返回 0，无目标写入。`0x2003` 非零分支传 1，零分支传 0。

同固件补充实现 `0x60093b90` 写 `0x2c42 / mask 0x02`，`0x60094a10` 写 `0x2c42 / mask 0xff`，都属于由 `InitializePeripheralSchgMisc` (`0x6018e9c7`) 初始化的 HAL 表的槽 `+0x3c`。这只证明相同地址还有 Misc HAL 实现，**不能确定槽名**。本轮对 `PmSchgMisc_SetChEn`、`PmSchgMisc_SetSmbEnCfg`、`PmSchgMisc_SetSmbEnResume` 的 combined-immediate 与 raw pointer 搜索均未找到直接引用。

缺少的精确定义为：本机对应 PMIC/外设版本的 `0x2c42.bit1`、`0x2c42.bit0`、`0x2c43.bit0` 的字段名、有效极性、硬件效果、访问/恢复要求，以及 HAL 槽 `+0x3c` 的具名绑定。现阶段不得命名为 charger enable、SMB enable、BATFET 或 battery disconnect。

## 5. ctx+0xc0 的 +0x60：0x2641/0x2341 编码

`+0x60` 绑定 `0x60136710..0x60136784`。函数将参数取低字节，使用 mask `0x07`：

| 对象条件 | 地址 | 写入数据 |
| --- | --- | --- |
| 模型 `0x56` 且对象 `+0x18` 字节为 1 | `0x2341` | 参数低字节，最终有效低 3 位 |
| 其他条件 | `0x2641` | 同上 |

`0x2003` 非零分支调用参数根据外层 MCA 模型选择：`0x4c` 为 4，其他为 5；零分支参数固定 4。外层 MCA 模型与这里用于选择寄存器地址的 provider 对象模型不能擅自等同。

目前只能称其为写入编码 4/5 的字段操作。缺少本机对应外设版本的 `0x2641[2:0]` 与 `0x2341[2:0]` 字段名、枚举 4/5 的含义和允许的转换。没有证据称为 charge mode、FET mode 或 bypass mode。

## 6. ctx+0xc0 的 +0x90：0x2842/0x2442 及前置写入

`+0x90` 绑定 `0x60137590..0x60137760`。模型跳转表从 `0x32` 起共 40 项，实际支持的分支如下：

| 对象模型/通道条件 | 操作顺序 |
| --- | --- |
| 模型 `0x32/0x47/0x4c/0x59` | 全字节写 `0x28d0=0xa5`，再 masked 写 `0x2842 / mask 0x70` |
| 模型 `0x56`、对象 `+0x18=0` | 同上 |
| 模型 `0x56`、对象 `+0x18=1` | 只写 `0x24d0=0xa5`；该分支中没有后续 `0x2442` 字段写入 |
| 模型 `0x56`、对象 `+0x18=2` | `0x28d0=0xa5`；`0x2842 / mask 0x70`；`0x24d0=0xa5`；`0x2442 / mask 0x70` |
| 其他模型或 `0x56` 的其他通道值 | 返回 `0x201` |

masked 写的数据为参数低字节。`0x2003` 非零分支传入 `0x30`；在实际写字段的分支，它令 `[6:4]` 为编码 3。本轮没有对应字段名字，也未独立确认前置 `0xd0=0xa5` 的寄存器定义，故只描述程序观察到的顺序，不把它升格为解锁操作的硬件文档证明。

精确缺口为：本机对应外设版本的 `0x2842[6:4]`、`0x2442[6:4]`、`0x28d0/0x24d0` 定义及编码 3 的意义；还需对象 `+0x18` 的运行时值与板级通道映射。

## 7. 返回值与恢复仍是实施阻断点

`0x2003` 在 `0x600314d4` 调用主充电开关，并在 `0x600314d8` 保存主返回值。后续所有上述附带调用的结果没有参与外层最终返回；最终 `0x600322b8` 仍返回主状态。主调用失败后，代码也没有通过其失败状态跳过附带操作。

非零分支的 FSW `+0xd4(3,5000)` 和 `+0x90(0x30)` 在零分支没有对应恢复。其余分支以固定参数执行，不读取并保存旧字段值；它们也不是已经证明的完整 restore。一个成功 ACK 或 `0x2003` getter 的 enable bit，不足以证明所有字段达成、可恢复或输入继续供 SYS。

因此，这轮不会把附带函数地址包装成插件可写接口，也不会以手机试写来替代缺失字段定义。

## 8. 本轮调查的有界终点

已完成目标五个实现、2004 同业务调用、相关 jump table、全部目标地址的直接立即数命中，以及同固件候选名字的限定引用调查。限定引用的负结果只说明未找到直接 combined-immediate 或原始 32 位指针，不证明任何形式的计算引用都不存在。

继续扩大不具名函数扫描可能产生更多相同偏移候选，但不能补足硬件定义。下一步有价值的离线输入是 **精确对应本机 PMIC 型号/修订的寄存器头文件、HAL 接口表定义、枚举或板级电源原理资料**；运行时身份也须另行经主审批准的只读方案取得。没有这些证据，本轮在以上精确缺口处结束，不以无限扫描或非匹配 SMB5 文档替代。

所有结论对照实际字节和正确解码器，仍只建立软件语义，不能单凭静态程序证明外部供系统、电池净电流为零或电池物理隔离。
